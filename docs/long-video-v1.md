# v1 手动长视频：实现与使用

本轮只修改 `app`，不修改 `localdream-v2`。使用 `templates/h3/workflow-longvideo-motion-context.json` 的 Ref2VA + Motion Context 分支，不覆盖原工作流。Agent 自动拆提示词、自动合并、工作流模板管理和画布功能均不在本轮。

## 操作方式

1. 在创作方式选择「长视频」。自动模式默认在目标时长 ≥10 秒，或 ≥8 秒且去重参考素材数 ≥3 时进入长视频编辑器；普通模式可以显式覆盖自动判断。
2. 在第一段设定比例、分辨率，然后逐段填写提示词、参考素材、**有效时长**、步数与 Ref2V LoRA。长视频也允许不使用参考素材。
3. 设置连续生成段数。后续段可以先留空，不必为了生成第一段而提前填写内容。
4. 「保存计划」只保存，并暂停后续分段启动；不会停止已经运行的片段。「开始生成／保存并继续」保存并启用连续执行。
5. 服务会依序生成已填写的片段；遇到空白片段等待补充，失败则停止推进。完成第一段后仍可补充下一段，或新建另外的视频。
6. 在「继续已有视频」选择历史计划，或从生成记录的「继续此视频」返回。每段有独立生成记录、进度、预览和下载，暂不自动合并。
7. 「暂停后续」不强制中断 GPU 上当前的片段。失败段可显式重试；在已完成片段上点击「从此段重生成」会把该段及其后的旧链标记为已替代、清空连续关系并重新生成。旧输出记录保留，便于对比。

未保存的编辑暂存在当前浏览器标签页的 sessionStorage；跨浏览器/设备续接应先保存计划。计划与配置正式保存在后端 SQLite，不依赖浏览器持续打开。

## 时长与续接

- 输入的是期望有效时长。后端先转换为帧数，后续段补上实际重叠帧，再按当前 H3 的 `17k+5` 帧网格向上取整。
- 原生时间轴固定为 **24 fps**；不是随意改变导出帧率就能保持音画正确。
- 默认视觉重叠 22 帧、音频上下文 24 帧，音频尾部对齐开启。视觉重叠可选当前节点支持的 5/22/39/56；上一段过短时，预测与节点一样退到可用帧数。
- 例如第一段期望 8 秒：192 帧，预计有效 8 秒。第二段期望 7 秒：168+22=190 帧，H3 取整为 192 帧，裁去 22 帧后有效 **7.083 秒**。总时长预计 **15.083 秒**。
- 第二段期望有效 8 秒时，214 帧还会被模型向上取整成 226 帧，预计有效 **8.5 秒**。页面同时显示请求时长、工作流输入时长和网格取整后的预计有效时长，不承诺任意小数秒精确输出。
- 手动模式不受建议 8 秒上限约束。模型节点自身最大帧数及实际显存仍然限制单段长度。
- 各视频使用 `h3_context/localdream/<sequence_id>/clip_<index>.safetensors` 对应的固定槽位；加载索引从 0 开始，保存索引从 1 开始，每段递增。实际文件名由 Save Latent 节点补齐到五位数。
- 每一段完成后都会保留对应的 `clip_00001.safetensors`、`clip_00002.safetensors` 等 latent 历史。最后一段重生成直接复用原计划和前一段 latent；中间段重生成会 fork 原计划，复制前缀和全部 latent 到新的 sequence 目录，原计划与原文件保留不变。
- Trim 的裁帧数始终连接 Motion Context 输出，不硬编码首段裁帧。上一段整个图（包括 Save Latent）成功后才开始下一段。

## 当前模板的限制

当前节点直接消费前一段 AV latent，明确拒绝空间尺寸改变。因此同一计划固定**比例和分辨率**，修改画幅应新建视频。这是模板的真实限制，不是新增的任意业务限制。

默认长视频编译图旁路 TE-Speed 包装节点，使用原生采样，Ref2V LoRA 仍可选择。TE-Speed 曾在本机 H3 版本上出现兼容问题；确认插件兼容后可在设置中显式启用。没有修改或安装 ComfyUI 插件。

设置包括默认模式、长视频阈值、多参考阈值/数量、默认段数/有效时长、建议输入时长、重叠帧、音频上下文、音频尾部对齐与 TE-Speed 开关。每个计划保存创建时的设置快照，全局修改只影响新计划。

保存全局设置后，未保存的新视频预览立即更新；「新建视频」会重新读取后端最新设置，清除旧计划关联。界面标明「最新全局设置」或「当前计划快照」，各片段列表显示输入时长与裁帧数。首段没有续接裁帧：目标 5 秒时首段输入始终为 124 帧（5.167 秒）；第二段重叠 22 帧时输入为 158 帧（6.583 秒），改为 5 帧时输入为 141 帧（5.875 秒）。

## 后端结构

保留模块化单体和现有 API，不引入微服务、容器、消息队列或空接口。`main.go` 只负责依赖组装、路由及生命周期。

| 职责 | 文件 |
| --- | --- |
| 业务类型和 ID | `domain.go`、`identifiers.go` |
| SQLite 与旧数据导入 | `store.go`、`legacy_import.go` |
| 素材及接口 | `assets.go`、`assets_http.go` |
| 生成接口、提交、恢复、进度与媒体 | `generations_http.go`、`generations_detail_http.go`、`generation_submit.go`、`generation_lifecycle.go`、`generation_progress.go`、`generation_video.go` |
| ComfyUI 图编译、通信及进程启动 | `comfy.go`、`comfy_process.go` |
| 模型提供方与现有导入接口 | `provider_http.go`、`workflow_import_http.go` |
| 长视频模型、配置、编译、调度和接口 | `long_video_model.go`、`long_video_settings.go`、`long_video_compile.go`、`long_video_service.go`、`long_video_http.go` |

SQLite 新增 `long_videos` 表和 `metadata.long_video_settings`；已有素材/生成记录不重建、不清空。子任务与计划内的任务关联在同一事务里保存，防止崩溃后重复创建当前段。已有生成任务继续使用原有提交意图、prompt_id/client_id 恢复机制。无法确认远端是否接收的任务不会自动重复提交。

SQLite 同时新增 `projects` 表；素材带 `project_id`，创作页选择项目后，`@` 候选和提交素材只来自该项目。素材库支持绑定/解绑项目。生成记录支持归档、取消归档、软删除和移动到项目；删除不影响已生成文件和任务快照。

主要接口：

- `GET/POST /api/config/long-video`：读取/保存全局设置。
- `GET/POST /api/long-videos`：列出/创建计划。
- `GET/PUT /api/long-videos/{id}`：读取/保存计划；PUT 带 revision，已提交片段不允许改写。
- `POST /api/long-videos/{id}/start|pause|retry`：继续、暂停后续、重试明确失败的当前段。
- 每段复用现有 `/api/generations/{id}` 与 `/video`，不再引入第二套进度协议。

## 验证与启动

已运行 Go 测试、vet、后端构建、前端 typecheck/build。新增测试仅覆盖时长/命名 widgets、模板编译与独立路径、顺序提交/空段等待/恢复/重试、设置快照和 HTTP 计划修改。测试使用临时数据库，不连接真实推理服务。

隔离 UI 预览使用临时 SQLite，并明确禁止生成，不启动 ComfyUI；已在浏览器检查桌面与窄屏页面、分段编辑、保存、刷新恢复和设置。

真实集成尚未验证：实现时 `127.0.0.1:8188` 拒绝连接，没有启动服务或提交 GPU 推理。可在 ComfyUI 正常运行后，通过环境变量 `COMFYUI_INTEGRATION=1` 执行 `go test -run '^TestCompileLongVideoAgainstComfyUI$' -v` 做只读节点元数据/编译检查。真实两段生成仍需要另外执行，确认视频、latent 文件和音画续接结果。

启动仍在 `app` 目录执行 `go run .`，前端已重新构建到 `frontend/dist`。旧的 `localdream.exe` 没有覆盖，不能用它验证新功能；需要二进制时重新运行现有打包脚本。
