# Local Dream：学习与交付新计划

更新日期：2026-09-10。本文档组是新的工作路线，不代表其中功能已经实现。

## 目标与边界

用一个真实、自用优先的 AI 媒体产品学习 Go 后端：用户选择素材和创作模式，系统验证输入、编译已验证模板、提交 ComfyUI，并可靠保存任务与结果。

优先级：实际可用闭环 > 独立解释与实现能力 > 可靠性 > 架构整洁 > 扩展性。

不再等所有底层模块整理完才接业务；不推倒现有原型，不以目录数、代码量、测试数量或“企业级”标签衡量进度。学习目标和产品验收分别记录。

## 三个必须交付的里程碑

1. **M1 动态素材闭环**：先只做 H3 多参考模式，完成查询、展示、后端校验、确定性绑定及真实生成验收。
2. **M2 可靠任务**：SQLite、单 worker、有界队列、取消、重启核对、作品保存。
3. **M3 可复现与试用**：扩展已验证模式，保存模板和生成参数，让另一位用户独立完成任务。

M4 多模板、Agent、分发增强属于可选扩展；没有 M1–M3 的证据，不推进“通用平台”。

## 协作约定

- 用户写业务代码；助手负责需求拆解、解释、只读审查、诊断和测试核对。除非用户明确授权，不代改代码、提交或重启服务。
- 可以复制测试 JSON、重复结构和工具配置；不要求逐字抄长代码。核心逻辑优先由用户先设计、先实现。
- 一轮包含需求、实现、审查、验证，不为每个 if 强制暂停。TDD 适合新规则和故障修复；已知常规逻辑可以先实现后补测试。
- 每完成一个切片，回答：解决什么问题、输入输出是什么、失败怎么处理、是否产生副作用、证据是什么。
- 新的正式决策写入相关文档；历史对话中的示例、百分比和工期不能代替当前代码证据。

## 进度和时间记录

使用“未开始 / 实现中 / 自动测试通过 / 集成通过 / 真实使用通过”，不再给缺乏工作量依据的完成百分比。

先用两次 60–120 分钟专注会话测出实际速度，再滚动安排后续任务。可先给 M1 一个约 10–20 个专注小时的探索预算，包含学习、调试和联调；这是预算而非承诺，模型运行时间另计。M2/M3 只在前一里程碑验收后估算。

若一个底层主题连续占用两次会话却没有推进产品闭环，回看是否过度抽象或缺少基础知识，及时缩小范围。
