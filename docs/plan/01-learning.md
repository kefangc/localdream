# Go 学习计划：从有指导实现到独立交付

## 当前判断

已经接触结构体、方法、指针、接口、JSON、错误包装、HTTP Client、context、表驱动测试和 httptest。现有代码和测试证明“能够在指导下实现”，不能直接证明“能够独立设计后端”。拼写失误本身不是能力结论，是否能独立定位根错误更重要。

不另开一条庞大的语法课程；以当前功能为主线，对不熟悉的语法做 10–20 分钟小练习后回到项目。

## 分阶段能力目标

| 阶段 | Go/工程主题 | 项目练习 | 独立验收 |
| --- | --- | --- | --- |
| L0 补强基础 | 静态类型、作用域、零值、值复制、切片/map、指针、接口方法集 | 看懂 RawMessage 与 []RawMessage；修复 := 和多返回值错误 | 不看答案列出每个表达式类型，并解释首条编译错误 |
| L1 HTTP 闭环 | handler、DTO、状态码、context、客户端与服务端区别 | 实现 capabilities 查询接口 | 独立新增一个错误分支及 httptest，不把业务判断写进 handler |
| L2 输入与协议 | JSON 缺失值、配置校验、外部 schema、错误分类 | 在线与离线能力解析，提交前素材校验 | 解释“未知上限”为什么不同于 0；独立写异常样例 |
| L3 数据存储 | database/sql、SQL、事务、索引、migration | 保存素材和任务元数据 | 重启后数据不丢；解释事务边界与磁盘文件一致性 |
| L4 并发与生命周期 | goroutine、channel、mutex、context、状态机、优雅关闭 | 单 worker、取消、恢复 | 不靠 sleep 写同步测试；解释取消竞态与终态保护 |
| L5 可维护交付 | 接口位置、依赖注入、结构化日志、配置、契约兼容 | 将旧任务流程逐步迁入模块 | 独立交付一个小变更并提供测试、日志和演示证据 |

## 每轮学习方式

1. 用自己的话复述需求，画出最多五步的调用流程。
2. 列出参数类型、返回值、三种失败情况和副作用。
3. 先写最小实现或测试；选择顺序要有理由，不强制所有任务都先 Red。
4. 编译错误先读第一条，再从变量声明、接收者和返回值追踪。
5. 审查时先解决真实缺陷，再讨论命名和抽象；不把所有建议都变成当前任务。
6. 合上示例解释实现，完成一个未见过的变更，确认不是仅记住答案。

可使用简短记录：

```text
日期 / 功能：
我先预测的行为：
我独立完成了什么：
需要提示的内容：
实际测试结果：
下次无需提示应能做到什么：
```

## 当前最合适的练习

- 给 Client 写“空节点名不发请求”的测试，自己选择计数/记录方式。
- 为 Catalog 区分调用者取消与探测失败；说明为什么不能吞掉 ctx.Err()。
- 自己实现返回固定能力的 HTTP handler，再把固定值替换成 Catalog 调用。
- 为新 API 写一个成功和一个未知模式测试，不先看完整答案。
- 用不同的 synthetic max 测试数据证明没有硬编码；不要为每个案例再抄一份长 JSON。

## 参考资料与使用顺序

- [A Tour of Go](https://go.dev/tour/)：补结构体、接口、切片等具体卡点。
- [Effective Go](https://go.dev/doc/effective_go)：理解语言习惯，不当成完整现代项目规范。
- [标准库文档](https://pkg.go.dev/std)：先查 testing、net/http、httptest、context、encoding/json、database/sql。
- [Go Race Detector](https://go.dev/doc/articles/race_detector)：开始 worker 后使用，先确认本机工具链支持。

课程或第三方框架不替代项目实践；也不要因为采用标准库就拒绝所有成熟库。

## 防止低效学习

- 手打不是目标。JSON 样例可复制并验证；把精力放在类型、约束和测试预期。
- 新测试直接通过可能是已有行为，也可能是假阳性，检查实际错误原因即可，不必人为制造失败。
- 测试数量不等于质量：要求准确边界、正确失败原因和真实副作用约束。
- 不反复练习已经理解的同类判断。两次能独立完成后推进新主题。
- “能运行、能解释、能独立修改”分别记录；不把一次跟写当作掌握。

## 阶段毕业任务

不看完整示例，实现一个“任务详情查询”或“按状态筛选任务”的小功能：自己定义 API、查询逻辑、错误策略、测试和说明。能解释其并发与数据库边界，才认定已具备这个切片的独立开发能力。
